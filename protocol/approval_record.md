# Approval record

The approval run of the public benchmark of the detector (Sismo), run once, on the frozen file of version 2 of the protocol.

The record was first written in Portuguese, like the protocol and the code of the approval run. This is its English translation; the
names of files, methods and rows are those of the publication code (section "Publication version"), and the old to new names are in
protocol/publication/keymap.json.

## The result

The full table, with the verdict of each row, is in README.md, generated by runner/table.py from the rows and the NAB score of the
approval run (linhas.json, sha256 8de7a6a1fcc7b1b43b9ec11d6cf129379a58e023660a1907f83019f1352b9b21, and nab.json, sha256
8b8c8ecc73dc613be7311709c9fdc84ef179a4b76e5de1ca6c566ff60a0a6995, in the approval outputs).

**The benchmark: FAILED.** Of the 18 rows that decide, 10 passed and 8 did not.

Passed: S1 (alert: 0.996 against 0.701 of the best competitor), S2 (log: 0.929 against 0.879), S3 (the right field: 0.996 against
0.438), S4a, S4b and S4c (direction, size and new normal, above the null), S5 (slow drift, tied at 1.000), S7 (nulls: an alert in 0 of
370 runs, a log in 6 of 370), M2 (incident, tied at 1.000) and M3 (regime change: 0.667 against 0 of the null).

Not passed, with what they show (nothing here changes the verdict):
- P1 NAB: the detector loses (0.165 against 0.405 of hddm_w). It finds 24 of the 43 events and gives 1.96 warnings per 1,000 items
  outside the labeled windows; on the shuffled series, 0.
- P4 SMD, P4o SMD where, P5 SMAP and P6 MSL: the detector's null exceeds the ceiling (0.1 warnings per 1,000 items) on the training
  stretch of the series (5.15 on SMD, 3.11 on SMAP, 2.20 on MSL; 0 on the shuffled series). On P6 the detector ties with the best
  eligible competitor. On P4, CJSD stays under the ceiling, with an F1 of 0.000, and the detector is above it. Only P4o has no eligible
  competitor.
- M1 contingency: the detector warns on the error field of the route in 7 of the 10 episodes (the best competitor, in 10); in the 7,
  the attributed start falls in the window.
- M4 drift: in one of the three normal lives the portfolio did not become the new normal, and in the no-drift life it did once.
- M5 return: the detector says "returned to normal" in 5 of the 7 episodes, between 681 and 815 minutes after the outage; the row asks
  for 180.

Declared limits (outside the verdict): L3 (XOR) confirmed (0 against 0.967 of CJSD). L1, L2 and L4 were not confirmed in this sample:
the detector was above the best competitor in all three (L4 on SMD, P4L4, the only public base with events shorter than 10 items).

Information only: NAB with a warm-up of 500 for every method (P1c: 0.213 against 0.351 of hddm_a) and the official NAB score. In the
latter, on the 36 approval series the detector scores 14.27 (HTM with the tuned threshold, 54.92); on the 58 series with the default

(competitors/check_htm.py, scores turned into warnings as in the benchmark, on the 58 series) gave 34.94, the same number the approval
measured for the default HTM on the 58.

## Publication version

The approval ran once, on the frozen code of 2026-10-12 (frozen file sha256
ed41901cf9662f62e12598e99573e58713a5e81504c7293e4543e57151606eb6, kept as protocol/history/frozen_approval_original.sha256; the seeds in
protocol/seeds.json were drawn from it). That code, its comments and its documentation were written in Portuguese.

For publication, the code, the comments and the documentation were translated to English and cleaned of internal remarks, with no
change meant to any computation. Files, methods, synthetic streams, configuration parameters, output keys and row labels were renamed;
protocol/publication/keymap.json maps every old name to the new one. A few defects that do not affect results were fixed:
- reproduce.sh: a failed check (frozen file, warning lists, table) now fails the script; before, the script printed nothing for a
  failed check and went on. It also checks its requirements before starting.
- runner/batch.sh: the cap of 4 lives of the company generated at a time did not hold under dash (the usual /bin/sh); it is now
  counted explicitly, and a failed background step fails the script.
- detector/trajectory.py: the index of a field was read from the default field name of the monitor (the digits after the last "c"),
  which broke with custom field names; it is now read from the index in the record.
- Dead code was removed.
- data/download.py: the default set of bases now includes the NAB scoring code and the label check, an unknown base is refused, and the
  value of --bases is no longer taken as the destination folder.
- data/build_htm.sh: the htm wheel is found by a glob (htm-2.2.0-*.whl) instead of a fixed file name for one platform.
- metrics/rows.py: every public base reports its L4 row, with n = 0 when the base has no event shorter than 10 items (the approval run
  wrote only P4L4).

The publication code was frozen as protocol/frozen_publication.sha256 (sha256 of that file:
7de3ed4948cd0975c30c2de535e626b637b1d08404c513b5156017e364ee14dc), in the same environment (protocol/ENVIRONMENT.txt has the same
package list as the approval environment file). The full approval was run again with this code and the same seeds, and every series was
compared with protocol/publication/compare_runs.py against the original outputs (protocol/publication/README.md explains how).

Result of the publication run (2026-10-14, 04:14 to 19:09 UTC): all 2,047 series were run with the publication code and the same
seeds, and compared with the original approval outputs: 2,047 identical, 0 different, 0 missing on either side (the warning lists of
every method and configuration, and the records and events of the detector). The run stopped once, at 06:22 UTC, because the machine
was restarted; it was resumed at 07:19 with the same command, which skips series whose output was already written (results/publication/log.txt).
The rows and the NAB score computed from the publication run are identical to those of the approval run (protocol/publication/compare_rows.py),
and the table they produce is byte-identical to the one in README.md. The only new rows are P1L4, P5L4 and P6L4, each with n = 0.
The warning list of every series of the publication run is in protocol/publication_warnings.sha256 (2,047 series; sha256 of the file
8f38378546de594429709b143d18066af97dc4ae6ae5ee422b58c625907f34d0). The rows, the NAB score, the table, the run log and the full output of
both comparison tools are in results/publication/ (rows.json sha256 8b2b85a35e698774ad337759418b42396ae7ac721779cc6f964a680500919cdf,
nab.json sha256 2c7a04c46056b74512b09e89d014a176f17bc040e0c1079bdb26279e064861f7; comparison.txt).

Why runner/legacy.py exists: two names are hashed, and the hash decides an order that reaches the last digits of some results. The
output file of a series is named by a hash of its key, the metrics read the outputs in file-name order, and the company rows resample
the lives in the order in which they first appear; and NAB sums the per-file scores in the order of its directory listing, whose names
start with the detector name. So the output file names and the NAB detector names are computed from the names of the approval run, read
from keymap.json, and the publication code writes the same file names as the approval run.

The outputs of every series of the approval run and of the publication run, and the simulated company lives, are published as a
dataset: https://huggingface.co/datasets/LimiarResearch/sismo-benchmark-runs.
